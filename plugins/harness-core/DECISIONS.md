# harness-core 결정 기록 — bash-guard

설계 정본: `docs/superpowers/specs/2026-10-14-bash-guard-design.md`(이하 spec). 구현 계획: `docs/superpowers/plans/2026-10-14-bash-guard.md`(이하 계획).
이 문서는 spec §2 의 확정 결정과 기각 대안, 계획을 고친 곳, 구현 중 확정한 결정을 모은다. 알고 받아들인 구멍은 [LIMITS.md](LIMITS.md).

수치는 이 저장소 개발 중 로컬 실측이다. 재생 수치는 로컬 세션 기록(공개하지 않음)에서 나왔고 명령 원문은 옮기지 않는다 — 예시는 모두 합성이다.

## 결정 요약

- 판정 축은 명령 모양이 아니라 **지워지거나 덮이는 대상의 성질**(세션이 만들었나 × 복구 가능한가)이다(D4).
- `on` 모드는 `ask` 를 내지 않는다 — 보호 대상은 즉시 거부 + 사유 + 대안(D2).
- 스위치는 프로젝트 settings 에만, 판정은 대상 저장소 기준(D10). 장부는 스위치와 무관하게 늘 기록(D14).
- 해석기는 표준 라이브러리 자체 어휘 분석기(D9). 구현 중 bash 의미를 제어 흐름·함수 호출까지 따라가도록 넓혔고, 따라가지 못하는 구문은 거부한다(아래 "모델링 불가 vs 구문 오류").
- 세션 시작 시각과의 모든 비교에 2초 여유를 둔다 — 이 호스트의 벽시계가 뒤로 간다(아래 "시각 여유").
- 최종 리뷰 뒤 원칙 둘(아래 "최종 whole-branch 리뷰 뒤 결정"): **훅의 모든 잠금·루프는 상한을 가진다**(R1), **조회 실패는 '모름'이지 '없음'이 아니다**(R2).
  그리고 해석기는 더 넓히지 않는다 — 새 구문은 미확정으로 떨어뜨리는 것이 기본이다. C3 는 이 원칙의 적용이다(아래 "C2 독립 점검 뒤 결정").
- C4~C7: 셸 호출 해석을 한 곳씩(옵션·stdin·장치 경로)으로, 명령 이름 확정을 한 질문(`resolve_command_name`)으로 모았다. 확정 면적을 넓힌 C5·C6 모델링이
  라운드마다 새 거짓 허용을 낳아 C7 에서 S1~S4 로 되돌렸고, 재검토 반복은 C7 에서 멈췄다(아래 "C4~C7 결정").

## 확정 결정 (spec §2)

| ID | 결정 | 근거 |
|---|---|---|
| D1 | 운용 모드는 bypass 고정. 플랫폼(auto 분류기)에 역할을 넘기지 않는다 | auto 는 멈춤이 더 잦다 |
| D2 | `on` 모드의 새 판정기는 ask 를 출력하지 않는다. 보호 대상은 즉시 deny + 사유 + 대안(`off`·`shadow` 는 현행 출력 그대로) | 기존 ask 471건 중 거절 0건, 멈춘 시간 합계 약 111시간. deny 는 Claude 가 경로를 바꿔 작업을 잇는다 |
| D3 | 판정 대상이 아닌 명령에는 지금처럼 allow 를 낸다 | 사용자 선택. bypass 에선 체감 차이 없음. auto 모드 분류기 우회는 알고 받아들이는 위험 |
| D4 | 삭제 대상은 이름이 아니라 출처 × 복구 가능성 7분류로 판정. git ignore 대상은 재생성 산출물 이름(`REGENERABLE_NAMES`) 안쪽일 때만 산출물 | "임시·테스트 데이터는 발동 금지, 설정·기본 파일은 보호"(사용자). ignore 대상에는 데이터·로컬 설정도 흔하므로 'ignore = 재생성 가능'은 거짓 |
| D5 | git 추적 파일은 일반 `rm` 거부, `git rm` 허용 | 삭제가 git 변경으로 명시·검토·복구 가능 |
| D6 | git 은 커밋 안 된 변경, 기본 브랜치 원격 덮어쓰기, reflog 파괴, 어디에도 남지 않는 커밋을 가진 브랜치 삭제만 보호. reset·rebase·기능 브랜치 강제 push 는 통과. `branch -D` 는 push 해 둔 상태·기본 브랜치에 내용이 들어감(병합·리베이스·스쿼시)·다른 ref 에서 도달 가능·이번 세션에 만든 브랜치면 통과 | reset·rebase 는 reflog 로 복구 가능. linked worktree 에서 만든 미푸시 커밋은 worktree 제거 뒤 reflog 에 남지 않는다. PR 흐름 무발동 요구 |
| D7 | 디스크 직접 쓰기·재귀 권한 변경은 작업 영역 안에서만 허용. 시스템 경로 쓰기 거부. `killall`·`systemctl stop/disable`·`rmdir` 허용 | 사용자 지정 |
| D8 | 컨테이너 안 명령의 경로는 컨테이너 기준으로 보고 허용. 호스트 마운트·이름 볼륨만 호스트 규칙 | 컨테이너 안 `/etc` 에 발동하던 것이 실제 문제였다 |
| D9 | 파이썬 표준 라이브러리만. 셸 문법의 필요한 부분집합을 다루는 자체 어휘 분석기. shlex·외부 파서 미도입 | shlex 는 따옴표 종류·리다이렉트 위치·`2>&1` 을 잃어 단위 분해가 틀어진다. bashlex 는 GPL·정체, tree-sitter 는 별도 휠 |
| D10 | 스위치 `HARNESS_BASH_GUARD=off\|shadow\|on`, 기본 `off`. 스위치는 프로젝트 settings 에만, 대상 저장소 기준 판정 | 단계적 전환·즉시 되돌림. 세션 env 로만 판정하면 홈에서 연 세션이 스위치 켠 저장소를 건드릴 때 꺼진다(코드읽기 가드의 2026-10-04 같은 결함) |
| D11 | 실패 정책 3종 분리(해석 실패·대상 확정 불가·내부 예외, spec §3.8) | Codex·Gemini·cc-safety-net 모두 셋을 구분 |
| D12 | 장부는 세션별이 아니라 공유 장부 하나. 다른 세션이 Write 로 만든·고친 파일은 이 세션 것으로 보지 않는다 | 같은 저장소를 여러 세션이 동시에 쓴다. 다른 세션이 Bash 로 만든 파일은 못 가린다(LIMITS) |
| D13 | 구현 중 feature 브랜치의 작업별 커밋은 사용자 위임. 테스트는 대역(모듈 패치·가짜 실행 파일·주입 데이터) 없이 인자와 실제 환경으로 | 저장소 규칙 '자동 커밋 금지'·'Mocking 금지'와의 충돌을 사용자가 결정 |
| D14 | 공유 장부는 스위치와 무관하게 늘 기록. `mv` 의 원본이 유일본·보호 이름이거나 이번 세션 것이 아닌 커밋 안 된 수정이 있는 추적 파일이면 목적지를 `moved-in` 으로 기록하고 분류 때 가장 먼저 본다 | 기록 시점에 꺼져 있던 파일을 나중에 켜진 판정이 오분류하는 경로, `mv` 로 재생성·임시 폴더에 옮겨 지우는 세탁 경로를 막는다. 비용: Write·Edit 마다 파이썬 약 35ms |

### 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| auto 모드로 전환해 분류기에 위임 | 사용자 운용과 충돌(멈춤 증가) |

| 외부 파서(bashlex, tree-sitter-bash, mvdan/sh) | D9 |

## 구현 중 확정한 결정

### 시각 여유 (`HARNESS_BASH_GUARD_CLOCK_MARGIN`, 기본 2.0초)

- **발견**: 테스트가 수백 번에 한 번 세션 저장소 오분류로 실패했다. 원인은 이 호스트의 벽시계가 약 30초마다 약 0.6초씩 뒤로 가는 것(journald `Time jumped backwards`, 200회 반복에서 2회 재현, 앞으로 가는 계단 0회). 나중에 만든 transcript 보다 저장소 폴더 생성 시각이 늦게 찍혔다.
- **위험**: 판정기는 '세션이 만든 것' 을 생성·수정 시각과 세션 시작 시각의 비교로 정한다. 역행이 있으면 세션 시작 약 1.3초 전 안에 만든 저장소·파일이 세션 것으로 단정돼 삭제가 허용된다 — 테스트 결함이 아니라 실사용 보안 결함이다.
- **결정**: 세션 시작에 기대는 모든 비교를 `target_class.before_session` 하나로 모아 `t < 세션 시작 + 여유` 면 세션 전으로 본다(모호 구간 = 보호 쪽). 적용 지점: 분류 5 `SESSION_NEW`, 분류 1b 저장소 폴더, `note_touch` 의 `pre-session` 기록, `is_session_change` 수정 시각, 다른 세션 `touched` 비교(`e.ts >= start - margin`), `branch -D` 생성 시각·`stash drop` 시각·docker 볼륨 생성 시각.
- **비용**: 세션 시작 후 첫 2초 안에 만든 것의 삭제가 보호된다(실사용에서 거의 없음).
- 환경 변수 값이 음수·파싱 실패·`nan`·`inf` 면 2.0 — `nan` 은 모든 비교가 거짓이라 허용 쪽으로 기운다.
- 테스트는 역행 자체를 감지해 세계를 다시 만든다(`WorldCase`: `time.time() - time.monotonic()` 이 0.01초 넘게 바뀌면 최대 3회 재시도, 재시도마다 stderr 한 줄). 계단이 없을 때의 실패는 그대로 실패라 진짜 결함을 가리지 않는다.
- 2.0초는 이 호스트의 실측 역행(연속 합 1.28초)만 덮는다(LIMITS).

### 빠른 길과 지연 줄이기

- 스위치가 대상 저장소 기준이라 모든 Bash 호출에서 판정기가 돈다. 실측 추가 지연이 p50 99~118ms 로 spec 수용치(35ms)의 약 3배였다.

### replay-fix — 재생 오탐 군집 수정의 결정

**임시 폴더 접두 + 마지막 구성요소 표식(H)**

- 재생 오탐 1위 군집: `{임시}/s1/$ID`·`run-$$`·`out-$(date +%s).txt` 처럼 임시 폴더 아래 마지막 이름만 변수인 대상. 정직한 실수 모델(spec §1.5)에서 그 값은 한 단어이고 다른 폴더를 가리키지 않는다.
- **결정**: 미확정 요소를 표식(hole)으로 채워, 표식이 마지막 구성요소 안에만 있고 접두 폴더(realpath)가 임시 루트 **하위**(루트 자체 아님)이며 그 폴더 분류가 `SCRATCH`(안에 보호 이름 없음)이고 대표 이름이 보호 이름이 아닐 때 그 대상을 '없는 새 이름'으로 본다(`shell_parse.expand_hole`·`policy._scratch_hole`).
- **표식 규칙**(적대 리뷰가 첫 구현의 '한 단어' 가정 위반을 찾아 좁힘): 큰따옴표 안 `$NAME`·`${NAME}`·`$$`·`$(…)`·백틱. 따옴표 없이는 `$NAME`·`${NAME}`·`$$`, 공백을 낼 수 없는 형식의 `$(date [-u] +형식)`, `$(uuidgen [-r|-t|-x])`. 표식 아님: 배열·`$@`·`$*`·위치 인자·`${X:-…}` 류 연산자 확장·`$_`·형식 없는 `$(date)`. 표식을 지운 이름이 비거나 `.`·`..`·`...` 면 확정 불가. 중괄호 여러 갈래·활성 글롭·확장 글롭·`~user`·xargs 입력이 섞이면 확정 불가.
- 이름 전체가 `$(basename …)`(operand 1~2개) 이면 값이 `..` 일 수 있으므로 접두 폴더의 **부모**를 분류해 `SCRATCH` 일 때만 허용한다.
- 받아들인 가정: 따옴표 없는 `$NAME` 값에 공백·글롭이 없다, 큰따옴표 안 값에 `/`·`..` 가 없다(LIMITS).

**실행 경로 집합 (`outcome`·`collect`·`join` + 도달 불가)**

- 적대 리뷰가 조건부·0회 실행 갈래의 대입과 cd 를 순차로 믿는 결함(예: 실패한 cd 뒤 상대 경로 삭제, `if` 안 대입)을 여러 모양으로 찾았다. 갈래마다 따로 고치면 반쪽이 됐다(`&&` 판을 고치니 `;` 판·조건 자리·그룹 안 exit 이 남음).
- **결정**: 각 구문이 만드는 끝 상태 집합을 세 함수 한 곳에서 합류한다. `outcome()` = 방금 끝난 요소의 (성공 끝, 실패 끝), `collect()` = 진행 중 `&&`/`||` 목록의 (성공 끝, 실패 끝), `join(states)` = 끝들의 합(비면 도달 불가 dead). `&&`/`||`·`;`·then/do/elif/else·fi/done·그룹·서브셸·case·`&`·`!`·`break`/`continue`·`exit` 가 모두 이 위에 있다. 값이 갈래마다 다르면 미확정.
- 실패한 cd 의 실패 끝은 cd 전 상태다 — 없는 폴더로의 cd 뒤 상대 경로는 미확정. 합류 비용은 쓰기 로그(`_Env`)로 바뀐 키만 비교해 갈래 수에 선형.

**성공 가정 집합**

- `&&` 합류가 정직한 명령 265건을 새로 거부했다(`mkdir -p D && cd D && …; 상대 경로`, `cd X && F=…; … $F`). 앞이 실패하면 뒤가 돌지 않는다는 것은 bash 의미로 맞지만 거의 늘 성공하는 단계까지 의심한 결과다.
- **결정**: 단순 명령 하나이고 리다이렉트가 없거나 무해(`/dev/null`·fd 0·1·2 복제)할 때만 실패 끝이 없는 것으로 본다: 대입만(치환이 모두 `mktemp` 이고 값 확정), `export`·`declare`·`readonly` 대입, `:`·`true`·`echo`·`printf`, 대상이 확정되고 상위가 있고 권한(`os.access`)이 있는 `mkdir`(8진 모드에 소유자 실행 비트), 있는 폴더이거나 앞서 만든 폴더로의 `cd`·`pushd`. 내장은 맨이름이나 `command`/`builtin` 밑에서만 내장이다(`./true` 는 외부 명령). 함수 밖 `local` 은 늘 실패하므로 제외. `command -v X` 는 진짜 조건 검사라 제외.

**`$( )` 안 heredoc·case·for 바인딩·`mktemp`**

- `$( )` 안 heredoc 은 구분자 줄까지 건너뛴다. bash 5.2 실측으로 `delim)`(구분자 바로 뒤 `)`) 줄은 끝이고 그 `)` 가 치환을 닫는다. 구분자로 시작하고 `)` 가 있는 다른 모양은 구문 오류로 둔다 — 본문으로 보면 bash 가 실행하는 다음 줄이 본문에 숨는다.
- case: 분기마다 시작 상태에서 출발, `;&`·`;;&` 는 시작·직전 끝의 합, `esac` 뒤는 모든 분기 끝의 합. 패턴 안 `$(…)` 는 해석 실패.
- for: 목록이 모두 확정되면(리터럴·중괄호·확정 변수·펼칠 수 있는 글롭, 50개 이하) 본문을 항목마다 해석하고 뒤 상태는 반복 끝의 합. 미확정·`+=`·`read`·`unset` 등 모델링하지 않은 변경이 있으면 루프 변수 미확정. 반복 총량 500, 재해석 글자 수 200,000 상한.
- `$(mktemp …)`: 결과 폴더가 실제로 있고 쓸 수 있을 때만 `{임시 루트}/bash-guard-mktemp-<고유>` 라는 '없는 경로' 로 확정. 호출 시점 `TMPDIR` 는 이름이 될 수 없는 내부 키에 담아 명령 안 재할당을 믿지 않는다. 결과 뒤 `..`·글롭은 확정 불가(실패해 빈 값이면 `/..`·`/*` 가 된다).

**함수 — 호출 지점 인라인 해석 (효과 요약 폐기)**

- 처음(라운드 4)에는 함수 호출을 일괄 미확정으로 두어 '정의 → 호출' 정직한 명령 96건이 거부됐다. 라운드 4b 는 정의 시점 본문의 쓰기 로그에서 효과 요약(cwd 변경 여부·쓴 변수 이름·부른 이름)을 만들어 그만큼만 미확정으로 했다.
- **요약을 버린 이유**: 쓰기 경로는 다 잡았지만 읽기와 실행 환경 — 호출 시점 cwd·전역 변수, 명령 자리로 흐르는 인자, 변수로 부르는 호출, 본문 안 서브셸 격리 — 를 반영하지 못해 bash 가 파괴하는데 허용하는 모양이 남았다.
- **결정**: 정의는 본문 소스를 기록하고, 호출 지점에서 그 본문을 호출 시점 상태로 다시 해석한다. `$1..$9`·`$#`·인자 여럿의 `"$@"`(명령 자리면 그 단어들로), `local`·위치 매개변수 복원, `return` 합류, `exit` 은 밖까지 도달 불가. 호출된 함수의 정의 시점 판정은 결과에서 뺀다(실제 인자로 다시 판정했으므로). 함수 판정은 래퍼 벗기기·내장 처리보다 먼저다(래퍼·내장 이름을 가리는 함수). 변수 명령 이름은 확정되면 그 이름, 아니면 cwd·변수 전부 미확정.
- 재생 효과: 라운드 4 의 정의+호출 99건 중 78건 허용.

**모델링 불가 vs 구문 오류 (spec §3.8 개정)**

- 인라인 설계가 새로 해석 실패로 보내는 모양(재귀·재정의 뒤 호출 등)이 spec §3.8(가) "해석 실패 + 위험 단어 없음 = 허용" 을 타고 100바이트~1.3KB 입력으로 `cp`·`mv`·`tee` 덮어쓰기를 숨겼다(재검토 17건). 위험 단어 목록에 이들이 없다.
- **결정**: 해석 실패를 둘로 나눈다. (가) 구문 오류·입력 불량(따옴표·heredoc 미종결, 짝 없는 예약어, `@(…)` 류 — bash 도 못 돌린다)은 지금처럼 위험 단어가 있을 때만 거부. (가′) **모델링 불가**(해석기가 알지만 따라가지 못하는 구문: 함수 재귀·상호 호출·재정의·갈래 정의 뒤 호출·`source`/`eval` 정의·`unset -f`·함수 안 함수·인라인 깊이 4/총량 200KB 초과·`break` 변수/범위 모양·본문 재해석 실패·`env -S`)는 bash 가 돌리므로 **위험 단어와 무관하게 거부**("해석 한계"). 구현은 `shell_parse.ModelError`(`LexError` 하위)·`ParseResult.unmodeled`·`bash_guard.R_MODEL`.
- 해석 마감(판정 예산)을 넘겨 멈춘 해석도 위험 단어와 무관하게 "판정 시간 초과" 로 거부한다 — 그러지 않으면 큰 입력에 `cp a b` 가 붙어 허용된다.
- 재생 비용: 거부 +8(정직한 모델링 불가 함수 호출 5건 등).
- 최종 리뷰 뒤 같은 원칙을 미확정 코드·목록 밖 docker 옵션·재귀 깊이·case 패턴 치환까지 넓혔다(아래 "R_DYNAMIC"). (가) 에는 bash 도 못 돌리는 구문 오류만 남는다.

**라운드 한도 뒤 처리**

- replay-fix 리뷰는 라운드 5 상한까지 돌았다(각 라운드 = 수정 → 적대적 재검토). 라운드 5 재검토가 낸 권고는 새 라운드를 열지 않고 **최종 수정 묶음 A** 로 처리했다 — 범위는 그 권고 목록으로 닫고, 고치지 않는 항목(이차 비용 잔여, `}` 뒤 heredoc, `cd X extra`, `popd`, `cd "$(dirname "$1")"`, `trap … DEBUG`, 실패하는 내장의 성공 가정, 서브셸 안 `mkdir`)은 LIMITS 로 옮겼다. 라운드를 더 열면 수정이 만든 결함을 다시 고치는 순환이 된다.
- 묶음마다 증거: 합격 묶음 동일성(125건 — 픽스처 59 + 이전 brief 입력 66), 적대 입력의 거부↔허용 전수를 bash 실측(파괴 여부)과 대조, 같은 조건 쌍 재생 귀속, 핵심 규칙 한 줄을 지운 변이 사본을 테스트가 잡는지.

### 최종 수정 묶음 B

- **장부 잠금 없는 기록**: 장부 잠금(flock)을 무기한 기다리면 훅 timeout 에 프로세스가 죽어 기록을 잃었다. 대기에 상한(판정 예산 마감, `touch-ledger` 는 3초, 마감 없으면 1초)을 두고, 넘으면 **기록을 포기하지 않고 잠금 없이 `O_APPEND` 한 줄** 을 쓴다. 기록의 부재는 보호 쪽이 아니다: `pre-session` 이 없으면 바꿔치기 저장된 세션 전 파일이 세션 생성으로 보여 삭제가 허용되고, `pre-dirty`·`touched` 가 없으면 남의 수정을 내 것으로 보아 `checkout`·`reset` 이 허용된다. 남는 손실은 그 순간 압축 rename 과 겹칠 때의 한 줄뿐(LIMITS). 중복 줄은 판정에 무해(any 검사).
- **`$'…'` ANSI-C 해석**: 명령 이름·경로를 `$'\x72m'` 처럼 쓰면 판정을 피하던 것. bash 와 19표본 바이트 동일.
- **환경을 바꾸는 래퍼**: `env -i`/`-u` 와 `sudo`/`doas`(기본 env_reset, `sudo -E` 는 보존)는 안쪽 코드의 바깥 변수를 미확정으로 본다. `env -C DIR`·`--chdir`·`sudo -D DIR` 는 명령 폴더로 모델링(처음엔 모델링 불가로 거부했으나 재생에서 정직한 사용 4건이 나와 바꿨다). `env -S` 는 모델링 불가. `busybox` 를 래퍼로.
- **자식 셸 export 모델**: 새 셸(`sh -c` 등)에는 export 된 변수와 접두 할당만 넘어가고 `PWD` 는 작업 폴더로 다시 정해진다. 환경에서 받은 변수 중 HOME·TMPDIR·USER·PWD 만 추적한다.
- **`find -exec`**: `-exec sh|bash -c '<코드>'`·`-exec busybox rm` 은 코드 안 삭제 명령 이름을 보면 확정 불가, `-exec /bin/rm` 은 미리보기로 실제 대상 판정.
- **기록 인코딩**: 판정 기록의 짝 없는 surrogate 는 `backslashreplace` — 전에는 기록이 통째 빠지거나 로그 파일을 못 읽게 했다.
- **단어 구분**: bash 실측대로 단어를 끊는 것은 공백·탭·개행뿐(`\r`·NBSP 는 단어 글자, CRLF 의 `\r` 은 마지막 단어에 붙는다).
- **`//` 경로**: 스위치 조회가 `//` 에서 끝나지 않아 판정기가 멈추고 훅 timeout 으로 판정 없이 진행되던 결함 — 루트 판정을 `dirname(p) == p` 로.
- 묶음 B 증거: 동일성 125/125, 변이 30/30 잡힘, 입구 off·shadow 바이트 동일 1,072/1,072, 재생 새 거부 1(미확정 변수 경로의 `git bundle create` — `>` 와 같은 규칙).

### 최종 whole-branch 리뷰 뒤 결정 (최종 수정 묶음 C·C2)

브랜치 전체 리뷰(묶음 B 뒤)가 Critical 1·Important 8·Minor 10 을 냈고 "C1·I1·I2 를 고치면 shadow 진행 가능" 으로 판정했다. 묶음 C 가 13항목을
처리하고(M7 보류), 그 재검토가 남긴 4건을 묶음 C2 가 고쳤다.

**R1 — 훅의 모든 잠금·루프는 상한을 가진다 (C1·I1)**

- 발견: 분류(`classify`)가 대상 경로마다 공유 장부 전체를 다시 읽었고 시간 예산 검사보다 먼저였다. 장부 3.8MB 에서 대상 100개 12.9초, 1,000개 107초 —
  훅 10초 한도를 넘겨 플랫폼이 **판정 없이 실행**한다. 장부는 모든 세션의 Write·Edit 마다 자라므로(압축 상한 5MB) 정직한 다중 대상 삭제가 이 경로에 든다.
  판정 기록의 잠금(`flock`)은 대기 상한이 없어, 잠금을 쥔 프로세스가 멈추면 deny 를 쓴 뒤에도 훅이 끝나지 않아 취소됐다.
- 결정: 장부 행 읽기 캐시 — 키 (inode, mtime_ns, 크기). 어느 프로세스의 `record()` 든 파일을 바꾸므로 프로세스 사이에서도 무효화된다. `touched` 기록은
  압축이 필요할 때 외에는 파일을 읽지 않는다. `classify` 입구에서 예산을 본다. 잠금은 `ledger.lock_file` 하나(비차단 재시도 + 마감 + 잠근 뒤 inode
  재확인)를 장부와 기록이 같이 쓴다. 기록은 `LOCK_WAIT`(1초) 안에 못 잠그면 순환을 건너뛰고 잠금 없이 한 줄 `O_APPEND` — 리눅스 로컬 파일 시스템에서
  `O_APPEND` write 한 번은 inode 잠금으로 다른 쓰기와 섞이지 않는다(순환 rename 과 겹치면 그 줄은 `.1` 쪽에 남는다).
- 결과: 같은 장부에서 대상 100개 0.79초, 1,000개·글롭은 예산 마감(약 5.1초)에 거부. 잠금 보유 중 deny 1.1초.
- 원칙: 훅 안에서 외부 상태(장부 크기·잠금·폴더 크기)에 비례하거나 그것을 기다리는 일은 전부 판정 예산 또는 고정 상한 안에 둔다. 훅 시간 초과는
  `shadow` 에서도 OLD 출력까지 없애는 회귀다(OLD 의 ask·deny 가 사라진다).

**R2 — 조회 실패는 '모름'이다, '없음'이 아니다 (I2·C2 I2-R)**

- 발견: 컨테이너 마운트 조회가 실패하면 허용했다. 데몬이 없을 때뿐 아니라 컨테이너 이름이 미확정(`docker exec "$C" …`)·없는 이름·compose 프로젝트 폴더
  모름·JSON 파싱 실패·Docker Desktop 바인드 경로 복원 실패까지 사유 없이 허용됐다. 고친 뒤 재검토는 데몬 부재 증거로 '클라이언트가 `PATH` 에 없음'을
  쓴 것이 절대경로 docker 호출을 허용함을 찾았다 — 파서는 docker 호출로 인식해 놓고 같은 명령을 '데몬 없음'으로 허용하는 내부 모순.
- 결정: 미확정·조회 실패 = 확정 불가(`UNRESOLVED`). 허용은 데몬 부재의 **긍정 증거**(소켓 부재)뿐이다. `tcp://`·설정된 컨텍스트는 소켓을 확인하지 않으므로
  증거 없음. 허용과 실패를 기록 `stats` 에 센다.
- 비용: 전수 재생 새 거부 45건 — 재생 시점에 그 컨테이너가 이미 없어 조회가 실패한 것. 실사용에서는 컨테이너가 있어 마운트 규칙으로 판정되므로 실제 빈도는
  shadow 의 `stats.container_lookup_none` 으로 본다.

**내부 예외 폴백 = OLD ∪ 위험 단어 (I3)**

- 발견: `on` 의 내부 예외 폴백이 위험 단어만 보고 OLD 를 보지 않아, 예외가 나면 `cp`·`mv` 덮어쓰기가 허용됐다(위험 단어 목록에 없다). 리뷰 권고는
  '판정이 시작된 뒤의 예외 = 거부'.
- 결정: 폴백의 정책 수준은 유지하고 OLD 와 합친다 — OLD 가 `ask`·`deny` 이거나 원문에 위험 단어가 있으면 거부, 둘 다 허용일 때만 허용.
- 이유: 예외가 OLD 수준 보호를 깎지 않는다는 보장이 이것으로 생긴다. 코드에서 포착되지 않는 예외 경로는 찾지 못해 빈도는 낮고, 전면 거부로 바꾸면 원인
  모를 예외 하나가 판정 대상이 아닌 명령까지 막는다. 폴백 발생은 기록 `error`·`fallback` 으로 shadow 에서 센다.

**R_DYNAMIC — 정적으로 알 수 없는 셸 코드 (묶음 C 항목 7·C2 (3))**

- 발견: `bash -c "$c"`·`eval "$x"`·셸에 넘기는 heredoc·`<<<` 의 미확정 코드, 목록 밖 docker 옵션, 재귀 깊이 초과, case 패턴 안 치환이 '구문 오류'(spec §3.8 가)로
  분류돼 위험 단어가 없으면 허용이었다. bash 는 이것들을 돌린다 — 모델링 불가(가′)와 같은 성질인데 분류가 달랐다. 그 결과 무관한 `>/dev/null` 하나로 거부가
  갈렸다. 재검토는 셸 stdin(`curl … | sh`·`cat f | bash`·`bash < f`)과 프로세스 치환(`bash <(…)`·`source <(…)`)도 같은 구멍임을 찾았다.
- 결정: `CodeUnknown`(`ModelError` 하위)으로 분리해 위험 단어와 무관하게 거부하고 사유를 따로 둔다("코드를 정적으로 알 수 없다 — 리터럴로 쓰거나 스크립트
  파일로 실행하라", `R_DYNAMIC`). 목록 밖 docker 옵션·재귀 깊이·case 패턴 치환은 `ModelError`(`R_MODEL`). (가) 에는 bash 도 못 돌리는 구문 오류만 남는다.
- 측정(같은 조건 쌍 재생 98,903건): 새 거부 35건(0.035%) — `sh -c "$var"` 30·`eval "$x"` 5, 전부 코드가 같은 명령 밖에서 온 변수. stdin 확장(C2)은 새 거부
  1건(원격 스크립트를 셸에 파이프). 이미 거부이던 129건은 사유만 올바르게 바뀌었다. 같은 명령 안 리터럴 대입(`c='…'; bash -c "$c"`)·for 변수·`mktemp` 는
  확정되어 새 거부에 없다. → **유지**(1% 이하).
- 의도적 허용: `ssh host "$cmd"`·`python -c "$code"` 는 이 호스트의 셸 코드가 아니라 대상이 아니다(LIMITS X1).

**덮어쓰기 표 확장과 `curl -o` 제외 (I5·I6·C2 I5-R)**

- 넣은 것: `ln -f`(기존 파일을 링크로 바꿔치기 — dotfiles 설정의 일상 명령), 출력 옵션 표 `_OUT_OPTS` 의 `wget -O|-o`(받기 실패해도 0바이트로 비운다)·
  `sort -o`(기존 파일을 비우고 쓴다), 래퍼 `setsid`·`strace`·`ltrace`·`runuser -u`, 셸 코드 래퍼 `su`/`runuser -c`·`flock -c`·`watch`, `trap` 코드 해석.
  긴 옵션 약어는 명령마다의 긴 옵션 표로 풀고 모호하면 확정 불가(`wget --output-do F` 를 놓치던 것).
- **`curl -o` 는 뺐다**: 실측상 기존 파일을 덮어쓰지만(연결 실패 때는 건드리지 않는다), 넣은 첫 재생에서 새 거부 683건 중 572건이 출력 옵션이었고 그중 curl 468건
  (전체의 0.47%) — 미확정 경로로 내려받는 루프와 재생 시점에 이미 있는 파일이었다. 위협 등급은 `>` 리다이렉트와 같은데 정직한 패턴 비용이 훨씬 크다. 되돌리기는
  `_OUT_OPTS` 한 줄(LIMITS). `wget`·`sort` 는 코드 원인 새 거부 26건(대부분 `cd "$D"` 뒤 `sort -o`), `ln -sf` 는 8건(세션 전 dotfiles 링크 바꿔치기 3 등)으로 유지.

**D3 닫힌 목록의 확장 기준**

D3(판정 대상이 아닌 명령은 허용) 때문에 목록 밖 래퍼·덮어쓰기 도구는 판정하지 않는다. 목록에 더하는 기준:

1. 위협 모델 안 — 정직한 실수로 되돌릴 수 없는 삭제·덮어쓰기를 일으키는 흔한 모양이다.
2. 이 호스트에서 동작을 실측했다(`--help` 의 값 옵션, 실제로 기존 파일을 바꾸는지).
3. 같은 조건 쌍 재생의 새 거부(정직한 패턴 비용)가 그 보호에 비해 작다 — `curl -o`(0.47%)는 넘었고 `wget`·`sort`(26건)·`ln -f`(8건)는 받아들였다.
4. 실측할 수 없는 도구(이 호스트에 없는 `parallel`·`unbuffer`)는 넣지 않고 LIMITS 에 둔다. shadow 에서 그 도구가 든 명령이 실제로 나오면 그때 1~3 으로 판단한다.

**K — 생성 시각이 없는 곳의 `created` 증거와 mtime 여유 (묶음 C 항목 8·C2 K-R)**

- 발견: `/mnt/c`(drvfs)는 생성 시각이 0 이라 세션이 만든 Windows 쪽 폴더도 늘 유일본으로 거부됐다(재생 69건). 판정기는 Bash 의 생성을 기록하지도 않았다.
- 결정: 판정기가 해석한 생성 목적지(`mkdir`·리다이렉트·`cp`/`mv`/`install`)를 `created` 로 기록하고, 생성 시각이 없는 경로에서만 이 세션의 `created` 를 생성
  시각 대신 쓴다. 생성 시각이 있으면 그것이 우선이고, 다른 세션의 `created` 는 증거가 아니다.
- 유령 기록: 기록은 판정 때 하므로 거부되거나 아직 실행하지 않은 명령의 목적지도 남는다 — 그 경로를 외부가 나중에 만들면 세션 것으로 보였다(재검토 실측). 그래서
  **파일 mtime ≥ 기록 시각 − `CLOCK_MARGIN`** 일 때만 증거로 인정한다. 외부가 기록 *전*부터 갖고 있던(mtime 이 과거인) 파일은 걸러진다.
- 여유를 두는 이유: drvfs 의 mtime 은 Windows 시계라 `time.time()` 과 수십 ms 어긋난다(실측 +0.014~+0.05초). 운영 여유 2.0초가 덮고, 어긋남이 2초를 넘으면 정상
  생성도 세션 전으로 보여 보호 쪽으로 틀린다. 남는 틈(기록 *뒤* 외부가 새로 만든 파일)은 LIMITS.
- 장부가 비활성(상태 폴더가 절대경로가 아님 — `HOME` 없음)이면 `pre-session` 을 볼 수 없으므로 세션 생성 판정을 하지 않는다(M5, 보호 쪽).

**M7 `NotebookEdit` 의 `created` — 보류**

Claude Code 도구 문서(code.claude.com/docs/en/tools-reference, "NotebookEdit tool behavior")는 NotebookEdit 를 기존 노트북의 셀을 하나씩 고치는 도구로 적는다 —
새 파일을 만드는 경로가 없다. 없는 경로에 `created` 를 남기면 그 경로를 남이 만들 때 세션 것으로 오인되는 유령 기록 위험만 키우므로 기록하지 않는다.
매처와 입력 필드(`notebook_path`)는 이미 장부 훅이 읽는다.

**해석기를 더 늘리지 않는다 (리뷰 설계 판정)**

- replay-fix 라운드 1~5 에서 나온 새 틈은 모두 같은 모양이었다: 새로 모델링한 구문(함수 인라인·for·case·local)이 확정값을 더 많이 만들면서, 그 확정이 틀릴
  수 있는 전제(범위·재바인딩·리다이렉트 실패·재정의)를 함께 모델링하지 않았다. 모델링을 늘릴수록 확정(= 허용) 면적이 늘고, 빠뜨린 전제가 fail-open 이 된다 —
  추상 해석기의 일반 성질이라 끝이 없다.
- 최종 리뷰의 적대 입력 174건에서 해석기 안의 거짓 허용은 `trap` 하나였고, 나머지는 판정기 밖의 명령 집합(D3)과 조회 실패의 해석(R2)이었다. 둘 다 유한한 목록·
  분기 하나로 닫힌다.
- 결정: 해석기는 더 넓히지 않는다. 새 구문은 미확정(거부)으로 떨어뜨리는 것이 기본이고, shadow 불일치가 그 구문에서 실제로 쌓일 때만 모델링한다. `trap` 은
  예외로 해석을 더했다 — 정리 패턴(`TMP=$(mktemp -d); trap 'rm -rf "$TMP"' EXIT`)이 흔하고 `mktemp` 모델링 덕에 과잉 거부 없이 닫힌다. 단 실행 시점 상태는
  모델링하지 않는다(LIMITS).

**그 밖 (Minor)**

- 죽은 코드 제거(호출처 없는 공개 함수·별칭·재수출), 시계 역행 수치 주석 통일, `assess` 가 판정 대상 여부까지 한 번에 돌려준다(`_host_jobs` 두 번 → 한 번).
- 스위치 settings 파일이 깨져 조용히 `off` 로 떨어지는 것을 기록 `settings_errors` 로 남긴다(파일 없음은 제외).
- 증거: 변이 묶음 C 19/19·C2 5/5 잡힘, 합격 묶음 동일성 122/125(다른 3건은 R_DYNAMIC 의 의도), 입구 off·shadow 바이트 동일 1,144/1,144, 이전 적대 입력
  881건의 거부→허용 회귀 0.

### C2 독립 점검 뒤 결정 (최종 수정 묶음 C3)

C2 뒤 독립 점검이 컨테이너·동적 stdin·wget·drvfs 장부에서 잔여를 찾았다. 묶음 C3 가 6항목을 고치고 나머지는 LIMITS·shadow 로 넘겼다.

**podman·데몬 직접 지정은 소켓 부재가 증거가 아니다 (R2 의 적용, I2-a·I2-c)**

- 발견: 데몬 부재 증거(docker 소켓 부재)를 띄운 CLI 와 무관하게 썼다. podman 은 데몬 없이 돌므로 docker 소켓이 없어도 컨테이너가 있다 —
  `podman exec <c> <삭제> /app/src` 가 허용됐다. 명령이 `-H`·`--context`·`DOCKER_HOST=` 등으로 다른 데몬을 가리켜도 훅 env 의 소켓만 봤다.
- 결정: 증거는 CLI 가 `docker` 이고(`Context.cli`) 명령이 데몬을 직접 지정하지 않았을 때(`Context.daemon_set`)만 쓴다. 그 밖의 조회 실패는 확정 불가.
  R2(조회 실패 = 모름)의 '긍정 증거' 가 그 데몬에 대한 증거일 때만 성립한다는 적용이다. `daemon_set` 은 할당뿐 아니라 해제(`unset`·`env -u`)도 센다 —
  해제 뒤의 기본 소켓이 훅 env 의 판단과 같은지 확인하지 않고 보호 쪽으로 둔다.
- 비용: 같은 조건 쌍 재생에서 코드 원인 판정 변화 0(이 모양이 말뭉치에 없거나 재생 조건에서 결과가 같다).

**`docker container create` 를 `run` 과 같게 본다 (I2-b)**

- 발견: 관리 명령 형태 `docker container exec|run` 을 인식하지 못해 판정 단계에 가지도 않았다(같은 명령의 `docker exec` 형은 거부). `stats` 로도 보이지 않는다.
- 결정: `container` 를 건너뛰어 `exec`·`run` 과 같게 본다. `create` 는 `run` 과 같은 인자로 컨테이너를 만들고 `start` 때 그 명령을 돈다(`docker container --help`
  실측) — create 시점에는 돌지 않지만 `run` 과 같은 표로 판정한다. **보수적 선택**: 그 명령이 실제로 도는 `start` 에는 명령 인자가 없어 판정할 자리가
  create 뿐이다. 비용은 create 만 하고 start 하지 않는 경우의 과잉 거부(드묾).

**`… | $VAR` 는 전부 확정 불가 (D4)**

- 발견: 파이프 대상 명령 이름이 변수·치환이면(`| $SHELL`·`| $(which sh)`) 셸일 수 있어 파이프 입력이 코드가 되는데, 이름을 몰라 셸 규칙을 타지 않았다.
- 결정: 파이프 입력이 있고 대상 이름을 확정할 수 없으면 `CodeUnknown`(`R_DYNAMIC`). `$PAGER`·`$PYTHON` 같은 정직한 변수도 거부된다.
- 근거: 같은 조건 쌍 재생에서 이 모양 0건(새 거부 0). 틀려도 거부 쪽이다. 같은 명령 안에서 리터럴로 대입한 이름(`P=less; … | $P`)은 확정돼 해당하지 않는다.
  과잉 거부의 실제 빈도는 shadow 에서 R_DYNAMIC 하위 사유로 본다.
  **C6 에서 대체**: 이 검사는 명령 이름 확정의 두 번째 구현이라 C6 이 `resolve_command_name` 으로 흡수했다(문구는 "명령 이름을 확정할 수 없음").
  하위 사유는 C5 부터 기록 필드 `dynamic_kind` 에 남는다(아래 "C4~C7 결정").
- 같은 묶음: stdin 장치 경로(`/dev/stdin`·`/dev/fd/0`·`/proc/self/fd/0`)·`source --`·옵션 끝 `-`/`--` 뒤 `<(…)`(이전엔 stdin 경로로 빠지던 버그)·`xargs … sh -c` 를
  같은 `CodeUnknown` 으로, 반대로 실행할 코드가 없는 `-n`·`< /dev/null` 은 허용으로 고쳤다.

**wget `--no-X` 는 정확한 이름만 (I5-a)**

- `--no-X` 를 긴 옵션 약어로 풀다 보니 정직한 부정형(`--no-continue`·`--no-quiet`)이 모르는 옵션 = 확정 불가였다. X 가 표에 정확한 이름으로 있을 때만 부정으로 인정한다
  (wget 1.21.4 실측: 약어 `--no-cont` 는 wget 도 거부). 출력 옵션 판정은 그대로다.

**K-c — birth 를 모르는 기존 파일의 제자리 수정은 `pre-session` 기록**

- 발견: K 의 mtime 조건은 유령 기록 경로에 옛 mtime 으로 나타난 파일을 **첫 수정 전까지만** 걸렀다. 세션이 그 파일을 `>>`·`sed -i` 로 한 번 고치면 mtime 이 갱신돼
  created 증거가 생기고 `SESSION_NEW` 가 됐다(F1·F3, 실제 `/mnt/c` 재현).
- 결정: 장부 기록 규칙(`target_class.note_touch`)에 "생성 시각을 모르고 이 세션의 created 증거(`created_evidence`)도 없는 기존 파일 → `pre-session`" 을 더했다.
  기록은 수정 *전*에 하므로 그 시점의 옛 mtime 으로 판단되고, 이후 mtime 이 바뀌어도 `pre-session` 이 우선한다. 증거 판정은 `created_evidence` 한 함수로 모아
  `SESSION_NEW` 조회와 기록이 같은 정의를 쓴다. 정상 생성 흐름(세션이 만들고 고침)은 증거가 있어 기록하지 않는다. birth 가 있는 파일 시스템은 기존 규칙 그대로.
- 남김: F2(외부가 옛 mtime 으로 만든 뒤 **외부가** 편집)는 판정기가 수정을 보지 못하므로 닫을 수 없다 — '외부가 기록 뒤에 손댐' 잔여와 같은 부류(LIMITS W30).

### C4~C7 결정 (최종 수정 묶음 C4~C7, 2026-10-17~18)

C3 뒤 재검토 → 수정 묶음을 네 번 더 돌았다. 묶음마다 앞 묶음 재검토의 열린 지적을 받았다. 아래는 최종 상태다 — 뒤 묶음이 앞 결정을 번복한 곳은 ③ 에 한 번만 적는다.
예시는 합성이다(`U` = 내용을 모르는 입력, `<삭제>` = 재귀 삭제 명령, `{HOME}` = 홈).

**① 근본 원인 — 셸 호출 해석이 부분 모델이었다 (C4 R-A·R-B·R-C, C5 보강)**

- 발견: C3 재검토의 N1·N2·OOS-1·OOS-2·D1·D2 는 한 뿌리였다. 셸 호출의 옵션·stdin·장치 경로를 손으로 쓴 부분 모델(`-n` 정규식, 첫 `</dev/null` 채택, 글자 그대로의 경로 목록)이
  맡았고, 모델이 모르는 모양은 '해석 없음 = 허용' 으로 떨어졌다 — `bash -n +n -c '<삭제>'`(실제로 실행), `bash </dev/null <<< '<삭제>'`, `bash -euo pipefail -c`, `U | bash //dev/stdin`.
  모양별로 덧대면 같은 일이 반복되므로 판단을 한 곳씩으로 모으고, 모르는 것은 확정 불가로 보냈다.
- R-A 옵션: `_shell_code` 의 옵션 루프 하나가 bash getopt 규칙을 쓴다(묶음, `o`/`O` 값, `-c` 플래그, noexec 표지와 해제, 모르는 옵션 = 확정 불가). 셸 인터프리터·컨테이너 안 셸·
  policy `_shell_deletes`(find -exec 셸 — 두 번째 손 모델이던 것)가 같이 쓴다. C4 재작성은 bash 의 한 대시 긴 옵션(`-posix`)을 짧은 묶음으로 쪼개 C3 의 거부를 허용으로 되돌렸다
  (C4 재검토 NB1 — 회귀). C5 가 '맨 앞 긴 옵션을 `-name`·`--name` 으로 먼저 소비' 를 더해 닫았다. zsh 의 `-o exec` 해제도 C5.
- R-B stdin: `_stdin_redirect` = fd 0(또는 생략)에 대한 마지막 입력 리다이렉트. `_stdin_code`·컨테이너 exec 의 stdin 전달·`_pipe_text`(cat heredoc)가 같이 쓴다.
- R-C 장치 경로: C4 는 '정리한 뒤 위험 목록과 대조' 였는데 C4 재검토가 `/proc/self/root/dev/stdin`·`/dev/fd/../../self/fd/0`·`/dev/stdi?` 로 새는 것을 보였다.
  C5 가 **허용 목록**으로 뒤집었다 — `/dev`·`/proc` 를 지나는 경로는 깨끗한 stdin 장치와 `/dev/null` 만 알고 나머지는 확정 불가(원칙 P1: 블랙리스트 대신 아는 것만 허용).
- 같은 묶음: 상태 env 를 확정할 수 없는 문장(`source`·동적 이름 할당) 뒤에는 데몬 부재 증거를 쓰지 않는다(`_forget` 이 데몬 변수 키를 '모름' 으로 남김, `--config`·`DOCKER_CONFIG` 추가 — C4 R-D),
  `touch` 를 제자리 수정 목록에(C4 R-E), 이름 붙은 fd `{var}<`(C5 OOS-A), find -exec 셸의 stdin 상속(C5 OOS-C), 기록 필드 `dynamic_kind`(C5 — 해석기 문구 그대로, 별도 코드 표 없음).
- 비용: C4 는 같은 조건 쌍 재생(98,903건)에서 판정 변화 0, C5 의 셸 해석 항목도 0 — 효과는 합성 시험·변이(C4 12/12, C5 13/13 잡힘)와 bash 5.2.21·dash 0.5.12·zsh 5.9 실측으로 증명된다.

**② 명령 이름 확정을 한 질문으로 (C5 OOS-B → C6 `resolve_command_name`)**

- 발견: "어느 명령이 도는가" 를 묻는 곳이 여럿이었다 — 단위 첫 단어(모르면 상태만 잊고 통과), 래퍼 뒤(C5 에서 확정 불가로 고침), env 할당 뒤(다시 검사하지 않음),
  xargs·find -exec·policy `_find_deletes`(첫 단어를 보지 않음), 파이프 대상(C3 D4 의 별도 규칙). 한 곳을 막으면 옆이 남았다 — C5 가 `env $X <삭제>` 를 닫자
  `env $X=1 $Y …` 와 래퍼 없는 `$X <삭제>` 가 남았다(C5 재검토).
- 결정: `shell_parse.resolve_command_name(word, env)` 하나가 정한다. `_strip_all` 이 할당을 벗길 때마다 부르고, 호출 지점은 단위 첫 단어(함수 조회 전에도 같은 함수)·
  컨테이너 exec 안 명령·xargs 의 명령·`find_exec_command`(해석기 find 갈래와 policy `_find_deletes` 공용)다. 파이프 대상 검사(C3 D4)는 같은 질문의 두 번째 구현이라
  흡수했다(그대로 두면 `| $B/vitest` 는 거부, `| $PY -` 는 허용으로 어긋났다). 확정하지 못하면 `NameUnknown`("명령 이름을 확정할 수 없음", `CodeUnknown` 의 하위).
- 예외 하나: 함수 정의 본문의 위치 매개변수(`$1`…`$9`·`$*`·`$@`) — 호출 때 인자로 다시 해석한다. C6 은 본문 안의 미확정 전부를 넘겼으나 `export -f` 뒤 `find -exec bash -c f`
  처럼 인라인하지 않는 호출이 있어(C6 재검토 #8) C7 이 위치 매개변수로 좁혔다.
- 같은 질문으로 닫은 것: `rbash`(C6), `coproc` 를 예약어로(C7 6a — 안쪽을 판정하고 상태는 서브셸처럼 되돌린다), find `-exec` 명령 자리의 `{}`(C7 항목 4), env 의 `=` 단어
  (치환이 든 단어는 확정 불가, 따옴표 안 할당 `env "A=1" <삭제>` 도 할당 — 이전에는 명령 `A=1` 로 봐 허용한 기존 구멍, C7 항목 3).

**③ 확정 면적을 넓힌 모델링을 C7 에서 되돌렸다 (S1~S4)**

- 경과: 과잉 거부를 줄이려 C5 는 '폴더만 모르는 리터럴 이름'(`$B/vitest`)을, C6 은 '값을 아는 변수의 단어 분리'·'할당 모양 추적'(`PY=$(…)/bin/python; $PY` → python)·
  '입력원이 있을 때만 확정 불가인 값 모르는 장치 경로' 를 더했다. 모두 확정(= 허용) 면적을 넓히는 모델링이다. 재검토마다 그 확장이 빠뜨린 전제에서 새 거짓 허용이 나왔다(C6 재검토):
  - 할당 모양이 사용 시점의 단어 분리를 무시했다 — `X=$(…)/ls; $X` 에서 치환 출력의 공백이 첫 단어를 바꾼다. C3 에서 거부이던 `X=$(…)/x; U | $X` 가 허용으로 **회귀**했다.
  - 단어 분리에 상한이 없어 약 300자 입력이 3GB·18초를 썼다(R1 위반, **회귀**).
  - IFS 를 상태 키로만 봐 산술 대입(`: $((IFS=5))`)·`trap 'IFS=5' DEBUG` 경로를 놓쳤다. 명령 단어 글롭(`/bin/r?`)·extglob 을 확정으로 봤다.
  - 입력원을 단위만 보고 정해 `bash $D/fd/63 <(…)`·`exec 3<<<…; bash $D/fd/3` 을 놓쳤다.
- 결정: 모델링을 더 넓히지 않고 "모델 없이 사실로 보이는 좁은 경우" 로 줄인다(spec §3.3 단계 6, 해석 범위 원칙).
  - S1: 명령 원문에 `IFS` 글자가 있으면 따옴표 밖 확장의 단어 분리를 확정하지 않는다(이름·대상 모두). IFS 를 바꾸는 경로를 하나씩 모델링하지 않는다.
  - S2: 따옴표 밖 값은 안전 글자 단어만, 16단어·1024자까지 나눈다. 한 단어의 확장 결과는 8192자(`_EXPAND_CAP`)로 묶는다 — 상한을 명령 이름이 아니라 `_subst` 에 둔 것은 대입 사슬이 값을 키우는 근본이 거기 있어서다.
  - S3: 이 명령에서 값을 모르게 대입된 변수는 따옴표 안(`"$PY"`)에서만 이름을 확정한다 — 할당 모양도 `$B/이름` 도 같다. 물려받은 변수는 §1.5 전제 그대로(`$B/vitest` 허용).
  - S4: 따옴표 밖 글롭 글자가 든 명령 단어는 이름을 확정하지 않는다.
  - 항목 2: 값 모르는 접두 경로의 '입력이 올 수 있음' 은 명령 원문 글자(`<`·`>(`·`coproc`·앞선 `|`)로 본다. 끝이 숫자면 늘 확정 불가.
- 되돌린 범위: C6 의 할당 모양 추적은 따옴표 안 사용으로만, 단어 분리는 안전 글자·상한 안으로만, 입력원 판정은 단위가 아니라 원문 글자로 좁혔다. 새로 더한 구문 모델은

**④ 단위 밖 stdin — stdin 셸은 단위에 적힌 입력만 받는다 (C7 6b)**

- 발견: 리터럴 `/dev/stdin` 도 `{ bash /dev/stdin; } <<< '<삭제>'`·`f() { bash; }; U | f`·`while …; do bash; done < x.sh`·`exec <<< …; bash` 에서 허용이었다(C6 재검토 OOS).
  C6 의 '입력원이 없으면 읽을 코드가 없다' 전제가 단위 밖에서 오는 stdin 에서 깨졌다. C3 의 W35 (b)(c)(`U | bash -c bash`·`exec < x.sh; bash`)도 같은 뿌리다.
- 결정: stdin 을 읽는 셸(`-c`·스크립트 없음, `-s`, stdin 장치 경로)은 단위에 입력원(파이프·stdin 리다이렉트)이 없으면 확정 불가("단위 밖에서 오는 표준입력의 코드를 확정할 수 없음").
  예외는 단위에 `< /dev/null`·`<&-` 를 적은 경우와 실행하지 않는 경우(noexec·`--help` 류)뿐이다. 그룹·함수·루프·`exec` 의 리다이렉트를 따라가는 모델을 만들지 않는다.
- 근거: 단위 밖 fd 를 따라가는 모델은 ③ 의 교훈대로 전제를 빠뜨리기 쉽다. 재생 새 거부 0건. 과잉 거부는 입력원 없는 `bash`·`bash -s`·`docker exec c bash`·`xargs sh`
  (GNU xargs 의 자식 stdin 은 비어 있다 — 실측) — LIMITS O28. 이전 X1 의 '입력원 없는 `bash -s` 허용' 은 이것으로 바뀌었다.
- 값 모르는 접두 경로(`bash "$X"`)는 같은 규칙을 쓰면 정직한 셸 스크립트 실행 약 900건(C6 근사 집계)이 거부되므로 원문 글자 기준(③ 항목 2)으로 따로 둔다.

**⑤ 재검토 반복을 C7 에서 멈춘다 (수정 라운드 정책)**

- 경과: C3 부터 C7 까지 묶음마다 재검토를 돌렸다. 재작성·확장이 회귀를 만들었다 — C4 재검토에서 1건(NB1), C6 재검토에서 2건(할당 모양의 `U | $X`, 단어 분리 상한).
  C7 재검토는 C6 지적을 모두 닫았고, 새 Important 6건은 모두 회귀가 아니다(기준 0b6fa85 도 같은 입력을 허용). 재검토 재현 입력 299건에서 거부 → 허용 회귀 0.
- 결정: 수정 라운드를 C7 에서 멈추고 남은 지적은 LIMITS(W37~W45 등)와 shadow 관측으로 넘긴다. 그중 한두 줄로 고칠 수 있는 셋(W37·W39·W40)은 **shadow 이후 첫 수정 후보**로 표시했다.
- 근거: 남은 것은 이번 원칙(S1~S4·항목 2~4)이 아직 닿지 않은 확정 경로이고 다수가 정직한 실수 모델(§1.5) 밖이다(16진 이스케이프로 짠 `IFS`, `I""FS`, `{rm,-rf}` 같은 명령 이름).
  라운드마다 수정이 다음 재검토의 재료를 만들었고, 정직 패턴 과잉 거부는 C5 40 → C6 93 → C7 109건으로 쌓였다. 더 돌리기 전에 실사용 빈도(shadow)를 본다.

### 병합 뒤 첫 수정 — W37·W39·W40 (2026-10-18)

- 결정: ⑤ 의 수정 후보 셋을 해석기를 늘리지 않고 **거부 방향으로만** 닫는다 — 원문 글자 검사(S1 `IFS`·입력원)를 풀린 중첩 코드에도 누적(W37), 명령 단어의 중괄호 확장 = 확정 불가(W39), find·xargs 가 셸 `-c` 코드 안에 넣는 `{}` = 확정 불가(W40). 위치 인자로 넘기는 `sh -c '…"$1"' _ {}` 는 그대로다.
- 증거: 실제 bash 5.2.21 로 재현 모양 12개 EXECUTED 확인(find `-exec … +` 판은 find 가 스스로 거부), 판정기 재현 입력 12개 ALLOW → DENY(정직 대조 5개 판정 불변), 변이 5/5 잡힘, 입구 off·shadow·on 1,782 비교 stdout·rc 동일(상태 차이 6 = 기존 mktemp 잡음), 같은 조건 쌍 재생(98,903, 변경 전 ea9b7aa 대비) 새 거부 27(0.027% — xargs `-I` 의 `-c` 코드 안 `{}` 26, find 1)·풀림 0·사유만 바뀜 2. 새 거부는 입력 줄·파일 이름이 코드가 되는 모양이라 받아들인다(고치는 길: `sh -c '…"$1"' _ {}`).

### 그 밖에 구현 중 정한 것

- 실패 정책 (다) 폴백: 입력을 못 읽어 명령을 꺼내지 못하면 stdin 원문 전체에 위험 단어 규칙을 적용한다(보수). 폴백 결과는 OLD 와 합친다(아래 "내부 예외 폴백"). 출력 인코딩까지 실패하면 ASCII 고정 바이트(`_SAFE`)로라도 allow/deny 를 낸다 — 빈 출력은 입구가 OLD(ask 포함)를 내게 한다.
- 시간 예산이 바닥났을 때는 끊긴 자리 뒤에 남은 단위 중 판정 대상이 하나라도 있으면 "판정 시간 초과" — 앞부분에 판정 대상이 없었다는 이유로 허용하지 않는다.
- 저장소 config 의 git alias 는 한 단계 펼쳐 판정한다(`-c alias.*` 포함). 명령 모양으로 판정 대상인지 모르는 단위도 조회 결과에 판정이 있으면 모드 계산에 넣는다.
- Docker Desktop 은 바인드 마운트 원본 경로를 `/run/desktop/…/<sha256>` 로 바꿔 저장한다(실측 30회 중 7회). `/proc/self/mountinfo` 로 복원하고 sha256 이 맞는 것만 믿는다. 복원 실패는 '조회 실패' — 처음엔 컨테이너 안 경로로 허용했으나 최종 리뷰 뒤 확정 불가로 바꿨다(아래 R2).
- 평범한 `git push`(강제·삭제·미러·`+ref`·`:dst` 없음)는 저장소 조회 없이 판정 대상이 아니다 — 재생에서 조회 실패(저장소 아닌 폴더 등) 때문에 거부되던 것. `push -o <값>` 의 값은 플래그로 세지 않는다(`-o -n` 이 dry-run 으로 오인되던 것).
- `/dev/tcp/*`·`/dev/udp/*` 리다이렉트는 bash 네트워크 가상 경로라 장치 쓰기가 아니다(`policy.DEVICE_EXEMPT`, realpath 로 `..` 탈출 차단).
- 경로 묶음 분류(`_classify_many`)는 경로마다 시간 예산을 본다 — `/mnt/c` 아래 수백 경로가 7.5초 걸리던 것.
