# harness-core 한계 — bash-guard

bash-guard 가 알고 받아들인 한계. 설계: `docs/superpowers/specs/2026-10-14-bash-guard-design.md`(이하 spec — §13 이 원래 목록), 결정: [DECISIONS.md](DECISIONS.md).

**이 판정기는 사고 방지 장치이지 보안 경계가 아니다.** 위협 모델(spec §1.5)은 "정직하지만 실수하는 에이전트" 다 — 의도적 난독화·악의적 우회는 처음부터 밖이다.

읽는 법:

- **분류** — W = 보호 약화 가능성(파괴를 허용할 수 있음), O = 과잉 거부(정직한 명령을 거부), X = 범위 밖(판정기가 다루지 않기로 한 영역·운영 비용).
- **모델** — 안 = 정직한 실수로 나올 수 있는 모양, 밖 = 일부러 감추거나 기이한 모양(위협 모델 밖).
- **지표** — 아래 "shadow 관측 지표" 의 번호. `—` 는 shadow 기록으로 볼 수 없는 것.
- 예시는 모두 합성이다(`{S}` = 임시 폴더, `{REPO}` = 저장소, `{HOME}` = 홈, `<삭제>` = 재귀 삭제 명령). 실제 세션 명령은 옮기지 않았다.
- 번호는 고정이다 — 해소된 항목은 맨 아래 "해소됨" 으로 옮기고 번호를 다시 쓰지 않는다.

## shadow 관측 지표

기록(`bash-guard.jsonl`, 필드는 README "장부와 기록")은 `on` 거부, `shadow` 의 신·구 불일치, 그리고 모드와 무관하게 내부 예외와 `stats`·`settings_errors` 가 있는 판정을 남긴다. 그래서 OLD 도 허용하고 `stats` 도 없는 보호 약화는 기록으로 볼 수 없다(표의 `—`) — 그 항목들은 재구성 테스트·적대 입력으로만 확인한다.

| 지표 | 보는 것 | 연결 항목 |
|---|---|---|
| M1 | `decision=allow` 이고 `old_decision` 이 `ask`·`deny` 인 줄 — 사람이 전부 검토해 새 판정이 틀린(파괴를 허용한) 사례를 센다. `on` 전환 기준: 0건 | W 전반 |
| M2 | `decision=deny` 이고 `old_decision=allow` 인 줄의 사유 종류별 빈도: "대상을 확정할 수 없다"(확정 불가), "해석 한계", "코드를 정적으로 알 수 없다", "명령을 해석하지 못했다", "판정 시간 초과", 유일본·추적·커밋 안 된 수정. "코드를 정적으로 알 수 없다" 는 그 줄의 `command` 를 다시 해석해 하위 사유("파이프 대상 명령을 확정할 수 없음" 등)로 나눈다(README) | O 전반, W28, X13 |
| M3 | `ms` 분포 — p99 와 4,000ms 이상 줄의 수, `budget_exhausted` 건수, `ledger_bytes` 추이 | W12, X5, X7–X9 |
| M4 | `error`·`fallback` 이 있는 줄(내부 예외·장부 기록 실패·출력 실패) — 모드와 무관하게 남는다 | W13, W21 |
| M5 | 대상이 `/mnt/c` 인 유일본 거부(mtime 보존 사본 `cp -a`·`tar x`·`rsync -a` 뒤의 정리 거부 포함) | O4, O21, O23 |
| M6 | 세션 기록의 `hook_cancelled`(Bash 훅 10초 초과 취소) 건수 — `bash-guard.jsonl` 밖, spec 부록 A 방법 | W12, X5 |
| M7 | `stats` — `container_lookup_none`·`compose_project_dir_none`(컨테이너 안 경로 확정 불가의 실제 빈도), `container_no_daemon`(데몬 부재 증거로 허용), `scratch_hole`(표식 가정에 기대 허용한 건수) | O17, W2, X14 |

## 해소됨

최종 리뷰 뒤(최종 수정 묶음 C·C2·C3) 닫혀 위 표에서 뺀 항목이다. 결정의 근거는 DECISIONS "최종 whole-branch 리뷰 뒤 결정".

| # | 원래 한계 | 해소 |
|---|---|---|
| W1 | 해석 실패 중 '구문 오류' 분류에 bash 가 돌리는 모양(미확정 `bash -c "$c"`·`eval "$x"`·셸에 넘기는 heredoc·`<<<`, 목록 밖 docker 옵션, 재귀 깊이 초과, case 패턴 안 치환)이 들어 있어 위험 단어가 없으면 허용 — 그 안의 `cp`·`tee` 덮어쓰기는 판정 밖, 무관한 `>/dev/null` 로 거부가 갈림 | 미확정 코드는 `R_DYNAMIC`, 나머지는 모델링 불가로 위험 단어와 무관하게 거부(O1·O15·O16). (가) 에는 bash 도 못 돌리는 구문 오류만 남았다. `>/dev/null` 로 갈리던 129건은 같은 사유로 통일 |
| W25 | Docker Desktop 바인드 경로 복원이 실패하면 '조회 실패' 로 보아 컨테이너 안 경로로 허용 | 조회 실패 = 확정 불가(O17). 허용은 데몬 부재의 긍정 증거(소켓 부재)뿐 |
| X1 일부 | 내용을 모르는 `… \| sh`(`curl \| sh`·`base64 -d \| sh`)는 해석하지 않고 통과 | 리터럴이 아닌 셸 stdin·`< 파일`·프로세스 치환은 `R_DYNAMIC`(O16) |
| O4 일부 | `/mnt/c` 의 세션 생성 폴더가 늘 거부 | Write·판정기가 해석한 생성은 장부 `created` 증거로 세션 생성(W30·O21 이 잔여) |

같은 묶음이 닫은, 이 문서에 오르기 전의 최종 리뷰 지적: 장부 전체 재읽기로 훅 10초 초과(C1), 판정 기록 잠금 무한 대기(I1), 컨테이너 조회 실패를 허용(I2)과 데몬 부재 증거로 클라이언트 `PATH` 를 쓴 것(I2-R), 내부 예외 폴백이 OLD 를 보지 않음(I3), `trap` 코드 미해석(I4), `ln -f`·`wget -O`·`sort -o`·`setsid`·`strace`·`su -c` 등 미판정(I5·I6 일부)과 `wget` 긴 옵션 약어(I5-R).

묶음 C3 가 닫은, C2 독립 점검의 지적(이 문서에 오르기 전 — 결정은 DECISIONS "C2 독립 점검 뒤 결정"): podman 과 데몬을 직접 지정한 명령에 docker 소켓 부재를 증거로 써서 허용(I2-a·I2-c), 관리 명령 형태 `docker container exec|run|create` 미인식(I2-b), 동적 stdin 의 stdin 장치 경로·`source --`·`-- <(…)`·파이프 대상 미확정·`xargs sh -c` 허용(D1–D5 — 남은 D6–D9 는 W35)과 반대 방향의 `bash -n`·`< /dev/null` 과잉 거부(O1·O2), wget `--no-X` 부정형 과잉 거부(I5-a — 빌드별 옵션은 O22), drvfs 에서 유령 기록 경로가 세션의 첫 제자리 수정으로 세션 것이 되던 것(K-c F1·F3 — F2 는 W30).

## 샌드박스 재검토 조건

Claude Code 샌드박스(bubblewrap)는 기각했다(DECISIONS "기각한 대안"). 다음 중 하나가 생기면 다시 검토한다:

1. 샌드박스가 Docker 와 함께 동작한다(지금은 `excludedCommands` 로 뺀 명령이 전체 권한으로 돈다).
2. WSL2 에서 샌드박스가 조용히 꺼지는 결함이 고쳐진다.
3. 위 X1(간접 실행 내부)로 인한 삭제 사고가 1건 생긴다.
