# harness-core 한계 — bash-guard

bash-guard 가 알고 받아들인 한계. 설계: `docs/superpowers/specs/2026-10-14-bash-guard-design.md`(이하 spec — §13 이 원래 목록), 결정: [DECISIONS.md](DECISIONS.md).

**이 판정기는 사고 방지 장치이지 보안 경계가 아니다.** 위협 모델(spec §1.5)은 "정직하지만 실수하는 에이전트" 다 — 의도적 난독화·악의적 우회는 처음부터 밖이다.

읽는 법:

- **분류** — W = 보호 약화 가능성(파괴를 허용할 수 있음), O = 과잉 거부(정직한 명령을 거부), X = 범위 밖(판정기가 다루지 않기로 한 영역·운영 비용).
- **모델** — 안 = 정직한 실수로 나올 수 있는 모양, 밖 = 일부러 감추거나 기이한 모양(위협 모델 밖).
- **지표** — 아래 "shadow 관측 지표" 의 번호. `—` 는 shadow 기록으로 볼 수 없는 것.
- 예시는 모두 합성이다(`{S}` = 임시 폴더, `{REPO}` = 저장소, `<삭제>` = 재귀 삭제 명령). 실제 세션 명령은 옮기지 않았다.

## shadow 관측 지표

`shadow` 기록(`bash-guard.jsonl`)은 새 판정과 OLD 가 다른 명령만 남긴다(필드 `decision`·`old_decision`·`reasons`·`ms`·`error`). 그래서 OLD 도 허용한 보호 약화는 기록으로 볼 수 없다(표의 `—`) — 그 항목들은 재구성 테스트·적대 입력으로만 확인한다.

| 지표 | 보는 것 | 연결 항목 |
|---|---|---|
| M1 | `decision=allow` 이고 `old_decision` 이 `ask`·`deny` 인 줄 — 사람이 전부 검토해 새 판정이 틀린(파괴를 허용한) 사례를 센다. `on` 전환 기준: 0건 | W1 및 전반 |
| M2 | `decision=deny` 이고 `old_decision=allow` 인 줄의 사유 종류별 빈도: "대상을 확정할 수 없다"(확정 불가), "해석 한계", "명령을 해석하지 못했다", "판정 시간 초과", 유일본·추적·커밋 안 된 수정 | O 전반, W1, W28 |
| M3 | `ms` 분포 — p99 와 4,000ms 이상 줄의 수 | W12, X5, X7–X9 |
| M4 | `error` 가 있는 줄(내부 예외·장부 기록 실패) — 모드와 무관하게 남는다 | W13, W21 |
| M5 | 대상이 `/mnt/c` 인 유일본 거부 | O4 |
| M6 | 세션 기록의 `hook_cancelled`(Bash 훅 10초 초과 취소) 건수 — `bash-guard.jsonl` 밖, spec 부록 A 방법 | W12, X5 |

재생 한계: 로컬 전수 재생(`tests/tools/replay_corpus.py`)은 세션 정보 없이 현재 파일 상태로 판정한다. cd 대상이던 세션 폴더가 그 뒤 지워졌으면 실시간에는 허용이던 명령이 확정 불가로 거부된다(라운드 4 귀속에서 새 거부의 90%). 재생 수치의 확정 불가는 이 몫을 빼고 읽는다 — shadow 의 M2 가 실시간 값이다.

## 샌드박스 재검토 조건

Claude Code 샌드박스(bubblewrap)는 기각했다(DECISIONS "기각한 대안"). 다음 중 하나가 생기면 다시 검토한다:

1. 샌드박스가 Docker 와 함께 동작한다(지금은 `excludedCommands` 로 뺀 명령이 전체 권한으로 돈다).
2. WSL2 에서 샌드박스가 조용히 꺼지는 결함이 고쳐진다.
3. 위 X1(간접 실행 내부)로 인한 삭제 사고가 1건 생긴다.
